# SwapCircle contributor instructions

Keep the code modular. Domain records live in lib/domain. Put provider access, exchange algorithms, orchestration and persistence in separate classes with injected dependencies. React components remain idiomatic function components.

Qloo suggestions are not consent. Never compare raw scores across separate Qloo queries. Missing results are unknown, not zero. Never silently replace failed live API calls with fixtures. Every fixture response must retain source=fixture.

Each physical copy has its own offer ID. Every matched member gives once and receives once. Declines, withdrawals and stale approvals must be enforced on the server. Approval binds to the exact cycle fingerprint and room revision. Real participants use separate capability links; host role switching is allowed only in the explicitly labeled demo.

Keep keys server-side and local environment files untracked. Never print secrets. Public endpoints need input limits, bounded provider calls and concurrency protection.

Use plain language. Do not claim adoption, measured satisfaction, revenue or environmental benefits without evidence. The fixture proves behavior, not Qloo ranking quality. Document test results separately from live API verification.

Do not edit another contributor's assigned files without coordinating. Do not commit or deploy unless the parent agent directs it.
